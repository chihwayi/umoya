# AI/Intelligence Subsystem Audit & Remediation Roadmap (S262+)

**Created:** 2026-08-26. Follow-up to the S246–S261 system-wide audit (see memory `project_audit_remediation_s246_s261` — that roadmap doc was deleted once fully resolved). This one covers a deep audit of the CDSS, PostVisit AI companion, Voice/Ambient/Copilot, and AI recommendation/ingestion subsystems specifically, run via 4 parallel deep-dive investigations.

**Golden rule carried over unchanged:** any per-tenant database schema change goes through `getProvisioningBundles()` in `services/tenant-service/src/services/database-provisioning.service.ts` — never a raw migration file. Read `docs/PROVISIONING_GUIDE.md` before touching schema. System-DB changes go in `TenantService.ensureSubscriptionSchema()`. Always run system-provisioning-then-tenant-repair in that order.

**Second rule, learned the hard way in the prior engagement:** `services/tenant-service/src/generated/tenant-entity-alignment.statements.ts` is a live, executed provisioning bundle — never `git checkout --` it to discard an unwanted diff. Regenerate (`npm run generate:tenant-provisioning-alignment`) and bump `BUNDLE_VERSION` instead.

### 1.4 Confirmed fine — do not re-audit

- **CDSS**: clinical safety governor itself (pure functions, correct escalation logic), risk-scoring formulas (Framingham, readmission, adherence — real clinical math), dosing calculator / duplicate-therapy checker / drug-interaction logic (real rule-driven, not hardcoded examples), NICU jaundice calculator (correct Bhutani nomogram with preterm adjustment), AI-governance safety-gate confidence/citation checks, acute job-failure handling (dead-letter queue works correctly), knowledge-ingest validation script (`ingest_guidelines.py`, checks RAG init + PDF existence before proceeding).
- **PostVisit**: grounded-LLM service's citation validation (rejects ungrounded output, has a circuit breaker, logs real errors — does NOT silently fake grounding), ambient-to-postvisit handoff (errors caught and logged, doesn't break the calling flow), telemedicine-postvisit bridge (async recording fetch doesn't block the response, errors logged with context).
- **Voice/Ambient**: the two transcription services are NOT duplicates — `TranscriptionService` (file-upload Whisper) and `VoiceTranscriptionService` (real-time CDSS with abstention logging) serve genuinely different purposes with no overlap. All voice/ambient/copilot SQL queries target real, correctly-provisioned tables. The retry-and-requeue pattern in `ambient.service.ts:59-87` is intentional, not a silent failure.
- **AI recommendation**: `followup-recommendation.service.ts` is fully implemented, not stubbed, with a real rule-based fallback on LLM failure. `ai-order-pipeline.service.ts` core save/approve/reject cycle is complete. `outcome-linkage.service.ts` is properly implemented. **The retraining/governance-honesty fix from the prior engagement (S253) is still correctly in place and has not regressed** — `outcome-collection.service.ts` still honestly reports `status: 'feedback_queued'`/`deploymentMethod: 'manual_review_required'` rather than claiming a fake auto-deployment.

## Definition of Done (applies to every sprint above)

1. No silent `.catch(() => {})` / empty catch on any path that (a) claims success to a caller while actually failing, or (b) is on a patient-safety, compliance, or escalation-delivery path.
2. Every fix verified against the *real* calling code, not just read in isolation — confirm reachability before and after.
3. Any DB schema change goes through `getProvisioningBundles()`, never a bare `.sql` file — golden rule.
4. `tsc --noEmit` clean in every workspace touched (not just the one nominally targeted — the `version: 1` bug from the prior engagement was missed exactly because of this).
5. Add or update a `.spec.ts`/pytest test for the specific failure mode being fixed, not just the happy path.
